## 二、验收 1：公开接口进入正确微服务

```bash
curl -s -X POST http://localhost/api/auth/register -H 'Content-Type: application/json' \
  -d '{"username":"testuser1","password":"123456","phone":"13900000011","role":"buyer"}'
# → 200 {"code":0,"message":"ok","data":{"token":"...","user":{...}}}  → user-service

curl -s http://localhost/api/products   # → 200 {"code":0,...,"data":[]}  → catalog-service
curl -s http://localhost/api/orders     # → 401 Unauthorized                → trade-service
```

| /api/products、/api/stores | catalog-service | 200 ✅ |

| /api/topics、/api/topic-posts | interaction-service | 200 ✅ |

## 三、验收 2：/internal/** 公网不可访问

```bash
curl -s -o /dev/null -w '%{http_code}' http://localhost/internal/users/1
curl -s -o /dev/null -w '%{http_code}' http://localhost/internal/products/1/snapshot
curl -s -o /dev/null -w '%{http_code}' http://localhost/internal/orders/1
curl -s -o /dev/null -w '%{http_code}' http://localhost/internal/sellers/1/summary
```

| 内部路径 | 实测 | 说明 |
|---|---|---|
| /internal/users/1 | 404 ✅ | Nginx 显式拒绝，不转发、不暴露 |
| /internal/products/1/snapshot | 404 ✅ | 同上 |
| /internal/orders/1 | 404 ✅ | 同上 |
| /internal/sellers/1/summary | 404 ✅ | 同上 |

隔离原理：`deploy/nginx/default.conf` 新增

```nginx
location /internal/ {
    return 404;
}
```

内部接口仅供服务间直连（K8s ClusterIP / compose 内网），公网经 Nginx 一律 404。

## 六、验收 5：失败回滚

回滚机制（`ops/remote-deploy.sh`）：

```bash
rollback() {
  kubectl apply -k "$previous_release/k8s"   # 回滚到上一 release 的 Kustomize 清单
  check_rollout_and_health                   # 回滚后再次健康检查
  ln -sfn "$previous_release" "$current_link" # 切换 current 软链
}
```

本地版本备份演示：

```bash
docker tag newsecondmall-user-service:dev newsecondmall-user-service:last-known-good
# 已备份 4 个服务的 last-known-good 镜像，可一键切回稳定版本
```
