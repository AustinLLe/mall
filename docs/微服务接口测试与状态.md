## 4. 状态定义

| 状态 | 判定规则 |
|---|---|
| 待迁移 | 新服务中尚无对应接口 |
| 开发中 | 负责人正在迁移，接口契约尚未冻结 |
| 待联调 | 已有实现，但运行环境、依赖或路由尚未完成 |
| 测试中 | 已编写并开始运行 HTTP API 测试 |
| 已通过 | 服务真实运行，HTTP 状态和关键响应断言全部通过并保存报告 |
| 阻塞 | 存在明确的外部前置条件，当前无法继续 |

“代码存在”或“单元测试通过”不能直接标记为“接口已通过”。

## 7. API 测试执行方式

### 7.1 Postman

导入：

```text
tests/api/soft-shop-microservices.postman_collection.json
```

服务直连变量默认值：

```text
user_url=http://127.0.0.1:8081
catalog_url=http://127.0.0.1:8082
trade_url=http://127.0.0.1:8083
interaction_url=http://127.0.0.1:8084
```

订单测试默认关闭：

```text
run_trade_flow=false
```

成员1提供可用地址后，设置 `address_id`，并将 `run_trade_flow` 改为 `true`。内部标记已售接口默认由 `run_destructive_internal=false` 禁止执行。

### 7.2 Newman

四个服务启动后执行：

```powershell
npx newman run .\tests\api\soft-shop-microservices.postman_collection.json `
  --reporters cli,htmlextra,json,junit `
  --reporter-htmlextra-export .\tests\api\reports\microservices\newman-report.html `
  --reporter-json-export .\tests\api\reports\microservices\newman-report.json `
  --reporter-junit-export .\tests\api\reports\microservices\newman-report.xml
```

如测试统一入口，将四个 `*_url` 变量都覆盖为成员5提供的统一地址。

## 8. 关键测试流程

### 8.1 基础服务流程

```text
创建买家 → 查询买家 → 内部查询买家
创建卖家 → 创建商品 → 商品列表 → 商品详情 → 商品快照
创建话题 → 话题列表 → 话题详情
```

### 8.2 跨服务订单流程

```text
准备买家和买家地址
→ 创建在售商品
→ trade-service 调用 user-service 校验用户和地址
→ trade-service 调用 catalog-service 获取商品快照
→ trade-service 在 trade_db 创建订单快照
→ catalog-service 幂等标记商品已售
→ 查询订单并校验 CONFIRMED
```

重点断言：

1. 相同 `clientRequestId` 重复提交不会创建两条订单。
2. 商品不存在时返回明确错误。
3. 用户或地址不存在时创建失败。
4. 商品服务不可用时返回 503，不能生成错误的已确认订单。
5. 订单保存商品名称和成交价格快照。
